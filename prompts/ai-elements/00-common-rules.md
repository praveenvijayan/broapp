# Common rules for every AI-Elements prompt

Read this file completely before starting any numbered prompt. These rules
override anything you remember about how Broapp, the AI SDK, shadcn or AI
Elements "usually" work. They also override the older
`prompts/ai-layer/00-common-rules.md` where the two disagree; where this
file is silent, that one still applies. Read it too.

## 1. What you are building

Broapp's chat panel is hand-rolled: `packages/broapp/src/ai/react/use-ai-chat.ts`
turns the `ai.chat` stream into messages, and `AiChat.tsx` renders them as
plain text. It has no attachments, no pasted screenshots, no markdown, and
every new feature is written from scratch.

This series replaces the *plumbing* with the Vercel AI SDK's `useChat` and
the *panel* with Vercel AI Elements, so those features come from standard
packages. The host — `ai.chat`, tools, the confirmation gate, secrets —
does not change its shape. One new workspace package holds everything the
browser needs.

Fixed decisions. Do not reopen them.

## 2. Repository conventions

Everything in `prompts/ai-layer/00-common-rules.md` §2 applies: Bun only,
TypeScript strict with `noUncheckedIndexedAccess` and `verbatimModuleSyntax`,
`.ts`/`.tsx` extensions on relative imports, named exports, `bun:test` in
`tests/`, no network in tests, `PublicError` codes only, no `any`, no
`@ts-ignore`, comments that say *why*.

Additions for this series:

- **Vendored code keeps its provenance.** Every file the AI Elements or
  shadcn CLI writes gets a one-line header comment:
  `// Vendored from ai-elements@<version> (<component>). Local changes are marked LOCAL.`
  and every edit inside it is wrapped in `// LOCAL: <why>` … `// END LOCAL`.
  A later upgrade has to be able to diff against upstream.
- **No path aliases in shipped source.** The CLI writes `@/components/...`
  imports. The package ships TypeScript source that a consumer's `Bun.build`
  resolves, so `@/` does not exist there. Rewrite every alias to a relative
  import before committing. A test greps for `from '@/` and fails on any hit.
- **Exact pins everywhere in the new package.** After any `bun add`, open
  `package.json` and remove every `^` and `~`.
- **No `instanceof` across bundles.** Use `isPublicError`, `fromTransportError`
  and `isValidationError` from `broapp/shared`. See
  `prompts/autoapp/reports/08b-fixups.md` step 3 for why.
- **Attribution.** Commit trailers follow the rule active in your session.

## 3. Verifying third-party APIs

Do not write AI SDK, `@ai-sdk/react`, streamdown or Tailwind calls from
memory. Before each one:

1. `node_modules/ai/dist/index.d.ts` — `ChatTransport`, `UIMessageChunk`,
   `UIMessage`, `FileUIPart`, `readUIMessageStream`, `ModelMessage`,
   `FilePart`.
2. `node_modules/@ai-sdk/react/dist/index.d.ts` — `useChat`, `UseChatHelpers`,
   `UseChatOptions`.
3. `node_modules/streamdown/dist/index.d.ts` and its `README.md` — props,
   CSS requirements, plugin split.
4. `node_modules/ai/dist/index.js` — when the `.d.ts` does not say how a chunk
   is *applied*, search for `case "<chunk type>"` and read the client-side
   processor (it is after line 7000).

If a name in a prompt differs from the `.d.ts`, the `.d.ts` wins. Note the
difference in your report.

## 4. Working method

Same as `prompts/ai-layer/00-common-rules.md` §4: read everything under
"Read first"; read every report under `prompts/ai-elements/reports/`; write
a five-line plan first; implement in order; run each step's verification
before the next; never loosen a test; finish with `bun install && bun run check`
both exit 0; write the report the prompt names (under 80 lines); one commit
per prompt with the message the prompt gives.

§5 of that file — what to do when unsure — applies unchanged: the
repository is right about how things work today, the prompt is right about
what to build; pick the option that changes the fewest files; never ask a
question mid-task; never leave a `TODO` and call it done.

## 5. Regression guard — things already fixed once

Each of these was a bug or a deliberate decision in an earlier pass. Your
change must not reintroduce it. When a step touches the area, re-read the
source named.

1. **`onToolResult` fires from the event handler, never from inside a React
   state updater.** React runs updaters when it chooses, so a read from one
   arrives too late for a callback (`prompts/ai-layer/reports/07-notes-docs.md`,
   bug 3). The transport calls back from its own `onEvent`.
2. **Usage counts come from the host's `usage` event.** The compatible
   adapter passes `includeUsage: true`; do not touch adapters (same report,
   bug 4).
3. **`expiresAt` reaches the confirmation card, and the launcher's window is
   ten minutes.** `LAUNCHER_CONFIRM_TIMEOUT_MS = 600_000` in
   `packages/broapp-autoapp/src/launcher/app.ts`; the card counts down with
   `countdown` / `isUrgent` from `broapp/shared` and turns amber under a
   minute (`prompts/autoapp/reports/08c-usability.md`). Never hard-code
   120 seconds anywhere in the browser.
4. **`onAwaiting(pending)` means "how many tool calls are waiting for a
   person right now".** The launcher uses it to prefix the tab title with
   `(n) ` and to raise a notification. Keep the exact semantics: called on
   every change, reset to 0 when the turn ends for any reason.
5. **Three settings states, not two.** `settings === null` → "Checking the
   AI settings…"; `configured === false` → "AI is not set up. Open Settings
   to choose a provider."; otherwise the chat (`reports/06-react.md`, open
   questions).
6. **Unmount cancels the stream, and cancel means `subscription.cancel()`.**
   Never cancel by abandoning an iterator (`docs/streaming.md`, skill hard
   rule 6). A `ReadableStream` you return must forward its own `cancel()` and
   the `abortSignal` to the subscription.
7. **Cancel keeps the text so far; send while running is refused, not
   queued.** The user asked to stop, not to undo.
8. **`ai.providersList` scopes a base URL to the provider it belongs to.**
   Do not touch `registry.ts` (`reports/07-notes-docs.md`, bug 2).
9. **Secrets never reach the browser, a transcript, or a log.** The
   transport sees `configured`, `hasKey`, `keyHint` and nothing else about a
   key. Do not add fields to `ai.settingsGet`.
10. **The host passes a model instance, never a model id string.** Only
    `ProviderAdapter.model()` makes one. No top-level `await` under
    `src/ai/host/**` (bytecode compile rejects it).
11. **`s.void()` tool inputs are normalised in `fromContract`.** Do not
    change tool-input handling.
12. **Off-origin is checked on CSS too.** `tests/build.test.ts` fails a page
    whose CSS carries `url(` or `@import`. Tailwind must be configured so the
    built stylesheet has neither; a test asserts it on the committed `styles.css`.
13. **Dark scheme defaults.** Commit `752b499` made the renderer's fields
    legible under `prefers-color-scheme: dark` without application
    variables. The new stylesheet must do the same: shadcn tokens map to the
    custom properties `ai.css` already reads, with literal light and dark
    fallbacks.
14. **Launcher plumbing is off limits.** Commits `c44be1d` (acceptance over
    IPC so the launch token stays unspent), `c4f1f9b` (tabs opened from the
    host), `6130990` (relative `BROAPP_DATA_DIR` resolved before a child),
    `66a569a` (child spawned from source when not compiled) live under
    `packages/broapp-autoapp/src/launcher/**`. Only `ui/App.tsx` and
    `ui/main.tsx` there may change, and only in prompt 04.
15. **The launcher page is built by `buildPage`** with inline CSS and a
    hashed CSP (`packages/broapp-autoapp/scripts/build-page.ts`). Nothing
    may add a `<link>` or a second stylesheet route.
16. **A release's identity covers everything it contains** (report 08b step
    1). Nothing here touches `broapp-autoapp` specs, releases or activation.
17. **Whitespace-tolerant hunks, `apps.list`** (report 08c) — engineer
    tooling; not touched.

## 7. Facts verified on 2026-09-07 against the installed packages

From `node_modules/ai/dist/index.d.ts` (7.0.93):

- `interface ChatTransport<UI_MESSAGE extends UIMessage>` has exactly two
  members: `sendMessages(options: { trigger: 'submit-message' | 'regenerate-message'; chatId: string; messageId: string | undefined; messages: UI_MESSAGE[]; abortSignal: AbortSignal | undefined } & ChatRequestOptions): Promise<ReadableStream<UIMessageChunk>>`
  and `reconnectToStream(options: { chatId: string; abortSignal?: AbortSignal } & ChatRequestOptions): Promise<ReadableStream<UIMessageChunk> | null>`.
- `UIMessageChunk` members this series uses: `start` (`messageId?`,
  `messageMetadata?`), `text-start` (`id`), `text-delta` (`id`, `delta`),
  `text-end` (`id`), `tool-input-start` (`toolCallId`, `toolName`),
  `tool-input-available` (`toolCallId`, `toolName`, `input`),
  `tool-approval-request` (`approvalId`, `toolCallId`, `approvalDescriptor?`,
  `reason?`), `tool-approval-response` (`approvalId`, `approved`, `reason?`),
  `tool-output-available` (`toolCallId`, `output`), `tool-output-denied`
  (`toolCallId`), `message-metadata` (`messageMetadata`), `error`
  (`errorText`), `finish`, `abort`.
- `FileUIPart = { type: 'file'; mediaType: string; filename?: string; url: string; ... }`.
  `url` is a data URL once AI Elements' `PromptInput` has converted a pasted
  or picked file. `convertFileListToFileUIParts` is exported from `ai`.
- `readUIMessageStream({ stream, message?, onError?, terminateOnError? })`
  returns an async iterable of `UIMessage` snapshots; the last one is the
  final message.

From `node_modules/ai/dist/index.js`, the client-side processor:

- `tool-approval-request` finds the tool part by `toolCallId`, sets
  `state = 'approval-requested'` and `approval = { id, descriptor?, requestReason? }`.
- `tool-approval-response` finds the part **by `approvalId`**, sets
  `state = 'approval-responded'` and `approval.approved`. So `approvalId`
  must be unique per call and identical between request and response.
- `tool-output-denied` sets `state = 'output-denied'`;
  `tool-output-available` sets `state = 'output-available'` with `output`.
- A tool part must exist (`tool-input-available` seen) before any of the
  above, or the processor throws.

From the registry:

- `@ai-sdk/react@4.0.96` depends on `ai@7.0.93` exactly and peers
  `react: ^18 || ~19.0.1 || ~19.1.2 || ^19.2.1`. Check the installed
  `react` satisfies this before pinning; if it does not, raise `react` and
  `react-dom` in the workspace root and say so in the report.
- AI Elements is installed with `bunx ai-elements@latest add <component>`
  (or `bunx shadcn@latest add https://elements.ai-sdk.dev/api/registry/<component>.json`).
  It needs a `components.json` and writes into the directory that file
  names. Its `prompt-input.tsx` imports `lucide-react`, `nanoid`, types from
  `ai`, and shadcn `command`, `dropdown-menu`, `hover-card`, `input-group`,
  `select`, `spinner`, `tooltip`; it handles paste through
  `clipboardData` items of kind `file`; `onSubmit` receives
  `{ text: string; files: FileUIPart[] }` with data URLs.
- `streamdown@2.6.0` renders markdown to React elements without raw HTML
  and takes `allowedLinkPrefixes` / `allowedImagePrefixes`. Code, math and
  mermaid are separate plugin packages and are not used.

From this repository:

- `ai.chat` params today: `{ runId, message (1–20,000 chars), refs (≤50), history (≤100 turns of { role, content ≤20,000 }) }`. `runId` matches `/[A-Za-z0-9_-]{8,64}/`.
- `ChatEvent` types and fields are listed in
  `packages/broapp/src/ai/shared/types.ts`. `confirm` carries `requestId`,
  `releaseId`, `argumentsHash`, `expiresAt`.
- `MAX_EVENT_BYTES = 4 MiB` in `packages/broapp/src/shared/ndjson.ts` bounds
  one stream *event*. Stream *params* travel in the Brobridge request; prompt
  02 measures whether a cap applies there rather than assuming.
- `BroappModel.capabilities.vision` exists; the fake adapter reports `false`,
  Anthropic `true`, the compatible adapter `false`.
- `AiChat` consumers: `examples/notes/src/ui/App.tsx` (props `refs`,
  `placeholder`, `onToolResult`) and
  `packages/broapp-autoapp/src/launcher/ui/App.tsx` (adds `onAwaiting`).
